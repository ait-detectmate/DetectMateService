    Usage

    DetectMateService provides a command-line interface (CLI) detectmate to manage the service.

    Quick start your first Service

    detectmate needs a settings file. To run a service with default settings only, create an empty one and start the service with it:

    Start service
    touch settings.yaml
detectmate --settings settings.yaml

    You should see output like:

    Create service settings

    To run the service with custom variables, we can define settings. For example, create a file named settings.yaml:

    Setting file
    component_name: my-first-service
component_type: core  # or use a library component like "detectors.RandomDetector"
log_level: INFO
log_dir: ./logs
http_host: 127.0.0.1
http_port: 8000
engine_addr: ipc:///tmp/detectmate.engine.ipc

    Start the service with settings

    To start the service, use the detectmate command. You can optionally specify a settings file and a component configuration file.

    Start server with setting file
    detectmate --settings settings.yaml --config config.yaml
    Flag Description
    --settings Path to the service settings YAML file.
    --config Path to the component configuration YAML file.
    --no-autostart Start the service without auto-starting the engine. Use POST /api/v1/start to begin processing.

    Starting in standby mode

    By default the engine starts automatically when the service launches. Pass --no-autostart to keep the engine idle on startup:

    Start service without the autostart
    detectmate --settings settings.yaml --no-autostart

    The HTTP API is fully available immediately. The engine stays idle until you trigger it explicitly:

    Call API
    curl -X POST http://127.0.0.1:8000/api/v1/start

    If the service has an API key configured, add -H "X-Auth-Token: <key>" to every /api/v1 request. See Authentication.

    This is useful for staged startup workflows where you want to validate configuration or wait for upstream/downstream peers to be ready before allowing data to flow.

    The same behaviour can also be configured persistently via the settings file or environment variable - see engine_autostart.

    Checking status

    To check the status of a running service run:

    Check Service
    detectmate-client --url <http_host:http_port> status

    Output:

    Output obtain
    {
  "status": {
    "component_type": "core",
    "component_id": "abc123...",
    "running": true
  },
  "settings": {
    "component_name": "my-first-service",
    "log_level": "INFO",
    ...
  },
  "configs": {}
}

    Reconfiguring

    You can update the component configuration of a running service without restarting it:

    Reconfigure Service
    detectmate-client --url <http_host:http_port> reconfigure new_config.yaml

    Add --persist to save the new configuration to the original config file (if supported).

    Reconfigure with persistency option
    detectmate-client --url <http_host:http_port> reconfigure new_config.yaml --persist

    Stopping the engine

    To stop just the processing engine, run the command below. The service process, its HTTP API, and any loaded component stay up, and you can restart the engine afterward with start:

    Stop engine
    detectmate-client --url <http_host:http_port> stop

    Stopping the process

    To shut down the entire service process (not just the engine) send SIGINT (Ctrl+C if it's running in your foreground terminal, as in the Quick start output above) or SIGTERM (what docker stop and systemd send), or call the shutdown endpoint directly:

    Stop the process
    curl -X POST http://<http_host:http_port>/api/v1/shutdown

    Unlike stop, this is not restartable, the process exits. After a signal, the last two log lines are:

    Logs of stoping Service
    [2026-10-14 13:25:22,345] INFO service.cli: Shutdown signal received (SIGINT)...
[2026-10-14 13:25:22,345] INFO service.cli: Clean exit.

    (SIGTERM logs SIGTERM in place of SIGINT.) The shutdown endpoint logs Process shutdown initiated. instead of the signal line, and also ends with Clean exit..

    If the engine is still running when the process shuts down, it's stopped automatically as part of teardown, so you don't need to call stop first.

    Controlling state persistency

    When a component has persistency configured, you can manage its saved state at runtime.

    Controling persistency
    # Show persistency config, event counters, and last save timestamp
detectmate-client --url <http_host:http_port> persistency-status

# Force an immediate save of learned state to storage
detectmate-client --url <http_host:http_port> persistency-save

# Restore learned state from storage (replaces current in-memory state)
detectmate-client --url <http_host:http_port> persistency-load

    These commands return 404 if persistency is not configured for the loaded component. persistency-load and persistency-import return 409 if the engine is running — stop it first, then load/import, then restart. See configuration.md for how to enable persistency via the persist block.

    Restore persistency
    # Download the current learned state to a file
detectmate-client --url <http_host:http_port> persistency-export detector_state.zip

# Restore state from a previously exported archive
detectmate-client --url <http_host:http_port> stop
detectmate-client --url <http_host:http_port> persistency-import detector_state.zip
detectmate-client --url <http_host:http_port> start

    Controlling training state

    By default a detector trains for a fixed number of events, then switches to inference-only mode. You can override this at runtime:

    Controlling training state
    # Check what the component is currently doing
detectmate-client --url <http_host:http_port> training-get-state

# Freeze the model, stop training immediately
detectmate-client --url <http_host:http_port> training-set-state stop_training

# Resume training: keep updating past the configured event limit
detectmate-client --url <http_host:http_port> training-set-state keep_training

# Force the configure phase on or off
detectmate-client --url <http_host:http_port> training-set-state keep_configuring
detectmate-client --url <http_host:http_port> training-set-state stop_configuring

    Valid values for training-set-state are keep_training, stop_training, keep_configuring, and stop_configuring. Any other value is rejected before the request is sent.
